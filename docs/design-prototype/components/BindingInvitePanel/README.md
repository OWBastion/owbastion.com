# BindingInvitePanel

为指定 BattleTag 生成 QQ 绑定邀请码，并可选授权一位历史持有者的未关联称号。仅管理员可用。

**结构**
- 卡片页眉：“生成绑定邀请码”加“管理员授权”胶囊。
- “目标 BattleTag”输入（占位“玩家名称#1234”）；格式错误时 `role="alert"`：“请输入完整 BattleTag，例如玩家名称#1234。”
- “历史称号”区：说明“请明确选择正确的历史持有者；不会按 BattleTag 自动匹配。”；搜索框（占位“搜索历史持有者或称号”）；持有者 `listbox`，每项“名称 + N 项未关联”，再点一次取消选择；选中后显示预览（至多 6 行，超出“另有 N 项”）。
- 提示“创建后，历史称号授权会在绑定成功后执行。”和主按钮“生成邀请码”；结果区显示 “名称#ID”、邀请码和“复制口令”（成功后“已复制”）。

**状态**
- 读取中：“读取中…”；空：“暂无未关联称号。”；详情：“读取持有者详情…”
- 提交禁用：BattleTag 无效、提交中、详情加载中，或已选持有者但详情未就绪。
- 错误默认：“无法生成邀请码，请稍后重试。”；复制失败：“无法复制口令，请检查浏览器权限。”

**无障碍**：`listbox` / `option` 加 `aria-selected`；预览 `aria-live="polite"`；各输入有 `aria-label`。

**合并建议稿（2026-10）**：原 `BindingInviteBatchPanel`（每行一个 BattleTag，批量生成并逐条复制）并入本组件：标题栏下增加“单个 / 批量”切换（两个 `chip`，`aria-pressed`）。单个模式保持原样（含历史称号授权选择）；批量模式是文本域加逐行校验（“第 N 行格式无效 / 重复”）加结果列表。两种模式共用 BattleTag 解析（`parseBattleTag`）、口令复制（`bindingInviteCopyText`）和结果行。批量不支持历史称号授权。删除原批量面板。
