# AdminChallengeDialog

为某个称号添加挑战或编辑挑战的对话框。挑战总是挂在称号下，头部显示所属称号和它的状态与范围。

**结构**
- 标题“添加挑战”或“编辑挑战”；称号名 chip 加“草稿 · 全局称号”这类说明。
- 完成规则（分段：截图条件 / 集齐指定地图）、完成条件*。
- 截图条件：截图规则（留空使用默认规则）、提交方式；地图称号另有地图版本、指定地图（留空作用于全部有效地图）。
- 集齐指定地图：统计范围、最低难度、要求地图*（开放时间内每张地图各有一条已验证通关即完成）。
- “开放”分区：添加模式有状态（分段：草稿 / 已开放）；开始时间（占位“立即”）、结束时间（占位“长期开放”）、引入版本。
- 称号已有其他获取方式时列出它们，并说明“玩家已持有这个称号时，不会从新挑战重复获得。”
- 底部“取消”和主按钮：添加模式“添加挑战”，编辑模式“保存”或“保存为新挑战”。

**状态**
- 添加到草稿称号且状态选“已开放”时，出现勾选的“同时启用称号「…」”，说明“称号还是草稿；不启用的话，挑战开放了玩家也拿不到。”
- 编辑时的保存方式分三档：
  - 获取资格变化（完成规则、要求地图、最低难度、适用地图）：顶部提示“保存后会新建一条挑战”，说明当前挑战会结束、新挑战接替、已获得称号的玩家不受影响；主按钮“保存为新挑战”。
  - 规则判断不了的改动（完成条件文字、截图规则、提交方式）：底部出现“这次修改怎么保存”，单选“原地更新”（默认，同一条挑战，已获得的记录和进行中的提交都不变）或“保存为新挑战”（当前挑战结束，新挑战接替）。
  - 只改开放时间或引入版本：原地更新，不提示。
- 保存中全部输入禁用、主按钮 loading；完成条件为空，或集齐模式下没选地图时主按钮禁用。

**Token**：外壳 `AdminResponsiveDialog`；资格变化提示用 `info` 浅底；分区标题 `quiet`、700，顶部 1px `line`。

**无障碍**
- 原生 form 与 `required`；分段控件是 radiogroup；保存方式是带 legend 的 fieldset。
- 资格变化提示用 `role="status"`，在切换后读出。
