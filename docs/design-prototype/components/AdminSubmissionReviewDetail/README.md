# AdminSubmissionReviewDetail

单条提交的审核工作台：汇总截图、字段核对、Challenge 判定，以及通过、驳回、要求重新提交等决定。

**布局**：容器宽于 56rem 时分两栏，左栏“提交截图”（`EvidenceViewer`）加字段核对，右栏“审核决定”卡片（`sticky`）；窄时单列，顺序为决定、截图、字段核对、Challenge、元信息。顶部元信息条：“名字#ID · 提交于 时间”，右侧状态徽章（待审核 / 已通过 / 已驳回 / 待重新提交）。

**决定卡片**
- “通过后玩家将获得”：称号名加类型（全局称号 / 地图称号），已拥有显示“已拥有「X」”；末行“同时记录一次已验证通关。”；空时“不会获得称号。”
- 按钮组（“审核决定”）：“通过”（主按钮）、“要求重新提交”、“驳回”（`error` soft）；其余低频操作收进“更多”；已通过时有“重新打开核对”。
- “自动判定抽检”面板：“确认抽检”“撤销称号”。“更多”中：“重新发送 OCRKit 请求”“识别准确”“识别有误”。
- 确认对话框：驳回、要求重新提交、重新打开核对、撤销自动获得的称号。

**状态**
- 无截图：`role="status"` “暂无截图。”
- “通过”禁用：无预览、预览不可通过、计算中、预览过期或正在提交；计算中提示“正在计算通过后的结果…”
- OCR 进行中：“正在重新识别截图，完成后自动刷新。”
- 只有被点击的决定按钮显示 `loading`。

**无障碍**：`section` 和按钮组有 `aria-label`；`aria-busy`；`#approval-hint` 通过 `aria-describedby` 关联；点击区域 2.75rem。

**建议稿（2026-10）**：元信息条用「名字#ID · 提交于 时间」；识别结果面板逐项列出需确认的字段与识别值，不再只写计数；去掉内部名 OCRKit 与英文 Verified Run；“更多”为明确入口。
