# AdminTitleWorkspace

称号页（/admin/achievements/titles）的工作区：一张称号表，每个称号行内展开它的获取方式（挑战或地图称号规则）。称号和挑战在同一处管理，自行请求 API。

**结构**
- 外壳是 `AdminWorkspace`：标题“称号与挑战”，操作区“新建称号”；下方 `AdminAchievementNav`。
- 工具栏一行：搜索（称号或完成条件）、系列、范围、状态、排序。
- `AdminDataTable` 列：展开、称号（名称加颜色）、系列、范围 · 展示方式、获取方式摘要、状态、操作。
- 获取方式摘要：“N 条挑战 · M 条可完成”；地图称号显示“地图称号规则”；没有挑战显示“无获取方式”。
- 称号操作：编辑；草稿称号“启用”；非草稿称号“发放”（打开手动发放并选中该称号）；已启用称号“退休”，已退休称号“重开”。
- 展开区标题“获取方式”，右侧“添加挑战”。每条挑战一行：完成条件（被取代的挑战附“完成条件变更后由上一条取代”）、提交方式、开放时间与版本、状态、操作。
- 挑战操作：编辑（已下线不可编辑）；草稿“开放”；已开放“计划下线”（就地浮层，填计划下线版本，提示“玩家侧会显示为即将结束。”）；已开放或即将结束“结束”；已下线“重开”。
- 地图称号的展开区是一张规则卡：规则条件、“由地图称号规则发放 · 适用范围”和“在地图挑战中管理”。不在这里编辑规则。
- 手动发放不是一行挑战，入口只在称号行的“发放”。

**状态**
- 称号状态由生命周期和挑战推导：草稿、已退休直接显示；否则按挑战取 已开放 > 即将结束 > 未开放 > 已下线；地图称号规则视为已开放。
- 新称号固定为草稿；草稿称号可以先添加草稿挑战，再“启用”，或在添加挑战时一起启用。
- 已退休且有挑战：展开区提示“称号已退休，下面的挑战不再产生新的获得记录；重开称号后恢复。”；没有挑战：虚线卡“已退休，没有挑战。仍可手动发放给指定玩家。”，不提供添加。
- 未退休且没有挑战：虚线卡“还没有获取方式，玩家无法获得这个称号。”加“添加第一条挑战”。
- 启用、退休、重开、开放、计划下线、结束、重开挑战都立即生效，页面底部提示“已退休「称号」”这类结果并给“撤销”；不弹确认框，不要求原因。
- 加载：骨架行，`aria-busy`，状态文字“读取中…”。
- 空：“还没有称号”加描边按钮“新建第一个称号”。
- 筛选无结果：“没有符合条件的称号”，列出当前筛选，给“清除筛选”。
- 读取失败：错误提示“无法读取称号 / 服务暂时不可用，请稍后重试。”加“重试”。
- 窄屏：同一批记录渲染为记录列表。卡片头是称号、系列与获取方式摘要、状态；展开后列出挑战（条件、状态、一行元数据、操作），底部“添加挑战”“编辑称号”“发放”“退休”。搜索常驻，其余筛选和排序收进“筛选与排序”。

**Token**：表头 `quiet`、700；展开行与展开区底色为 `surface-raised` 45% 混入 `surface`；挑战行和规则卡 `surface` 加 `line` 边框；空卡虚线 `line`；状态徽章走 `StatusBadge` 语气（已开放 `success`、即将结束 `warning`、未开放 `info`，其余默认）。

**无障碍**
- 展开按钮 `aria-expanded`，名称为“展开/收起 <称号>的获取方式”；展开区是带名称的 region，挑战表 `aria-label` 为“<称号>的获取方式”。
- 计划下线浮层是带名称的 dialog，关闭后焦点回到“计划下线”按钮。
- 撤销提示用 `role="status"`；状态都有文字，不只靠颜色。
- 展开、菜单和异步操作用称号和挑战的稳定 ID，不用数组下标。
