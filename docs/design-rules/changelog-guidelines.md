# 版本更新（Changelog）文案与排版规范

本文档是 Portal 中**版本更新（Changelog）** Markdown 内容编写的唯一权威规范。新增、维护或同步任何版本更新日志前，必须遵循本文档约定的结构、层级、文案风格与术语规则。

---

## 1. 定位与文件契约

- **内容定位**：`changelog`（Portal 展示为“版本更新”）**只收录已发布的更新内容**；进行中、预告或设计中的开发内容应写入 `blog`（开发日志）。
- **文件路径**：`apps/portal/content/changelog/{version}.md`
- **文件名格式**：`YY.MMDD.V.md`（例如 `26.0821.1.md`，代表 2026 年 8 月 21 日第 1 次发布）。

---

## 2. Frontmatter 结构与校验规则

所有 Changelog 文件必须以 YAML Frontmatter 开头，且必须满足以下字段契约：

```yaml
---
title: "帕拉伊苏重制版、英雄更新与随机事件调整"
description: "26.0821.1 已发布，更新主题为帕拉伊苏重制版、英雄更新与随机事件调整。"
releasedAt: 2026-08-21
version: "26.0821.1"
tags:
  - "版本更新"
---
```

### 字段说明与约束
- `title`：简明概括本次更新的核心模块（不超过 160 字符）。
- `description`：固定采用事实陈述句式：`"${version} 已发布，更新主题为${title}。"`（不超过 320 字符）。
- `releasedAt`：发布日期，必须为 `YYYY-MM-DD` 格式，与版本号日期严格一致。
- `version`：完整版本号字符串，格式为 `YY.MMDD.V`。
- `tags`：固定为 `["版本更新"]`，不使用已废弃的“版本记录”或自定义标签。

---

## 3. Markdown 层级与排版规则

1. **禁止在正文使用 H1 (`# `)**：页面大标题由前端根据 Frontmatter `title` 渲染，正文顶层标题一律从 H2 (`## `) 开始。
2. **严格的标题层级递进**：
   - 允许使用的标题层级为 `H2` (`## `)、`H3` (`### `)、`H4` (`#### `)。
   - **严禁跨级跳跃**（例如从 H2 直接跳至 H4）。
   - **严禁使用 H5 (`#####`) 及更深层级**。
3. **列表符号统一**：无序列表一律使用 `- `，不使用 `* `。子列表缩进统一为 4 个空格。
4. **禁止反斜杠转义字符**：正文中严禁出现 `\(`、`\[`、`\*`、`\.` 等无意义的 Markdown 反斜杠转义。
5. **严禁占位符**：禁止在已发布日志中残留 `xx`、`xxx`、未补全的空章节或草稿占位。

---

## 4. 核心模块排版范式

### 4.1 英雄更新
- 一级分区：`## 🕛 英雄更新`
- 英雄标题：`### [英雄名称]`
- 设计意图/背景说明：单行引用 `> 说明文本`（仅在确需解释原因时添加，简明扼要）。
- 改动条目：`- **技能名/属性（键位/说明）：** 调整内容`

```markdown
## 🕛 英雄更新

### 生命之梭

> 随着游戏本体现已支持被拖拽队友主动取消「生命之握」，模式内不再需要禁用该技能。

- **生命之握（技能 2 / E）：** 重新开放使用
```

### 4.2 地图更新与重制版
- 一级分区：`## 🗺 全新地图：[地图名]` 或 `## 🗺 [地图名] 重制版`
- 地图概述：国旗/地区 Emoji + 堡垒点位分布（如 `全图共计 9 个堡垒，综合分布为 3/3/3`）。
- 开服当日限定成就挑战：
  - 二级小标题：`### [Emoji] [地图名]开拓者 成就挑战（MM.DD）`
  - 达成奖励：`- 当日以**地狱**难度通关可获得 “**[称号名称]**” 地图限定称号`

```markdown
## 🗺 帕拉伊苏 重制版

🇧🇷 帕拉伊苏：重制版 现已登场！全图共计 9 个堡垒，综合分布为 3/3/3

### 🇧🇷 帕拉伊苏开拓者 成就挑战（08.21）

- 当日以**地狱**难度通关可获得 “**黄金节拍**” 地图限定称号
```

### 4.3 随机事件调整
- 一级分区：`## 🔃 随机事件调整`
- 标准分类（H3）：
  - `### 增益类事件 （好运降临）`
  - `### 减益类事件 （厄运缠身）`
  - `### 机制改变类事件  - 20% 概率`
  - `### 赌徒事件组机制改动`
- 具体事件（H4）：`#### [事件名称]`（重做事件标注 `#### [事件名称]（重做）`）
- 数值与规则调整：采用直观的事实对比或数值变化描述：
  - `所需治疗量由 10000 调整为 2500 + 500 × 玩家总数`
  - `在多合一地图中所需的目标由 3 降低至 2`
  - `持续时间由 90 秒降低至 60 秒`

```markdown
## 🔃 随机事件调整

### 增益类事件 （好运降临）

#### 任务：钢化你心

> 优化多合一模式推进目标。

- 在多合一地图中所需的目标由 3 降低至 2

### 机制改变类事件  - 20% 概率

#### 镜像反转（重做）

- 出现条件不再要求玩家同时拥有多个负面永久属性
- 不再一次性反转全部属性，现在会优先反转已有的负面永久属性

### 赌徒事件组机制改动

- 优化负心之钢状态下的交互规则：
    - 固定获得或损失心之钢的事件仍可正常参与
    - 需要以当前心之钢作为本金、按比例下注或按倍率计算的事件，在心之钢不足或为负数时不再出现
```

### 4.4 综合更新与模式更新
- 一级分区：`## 🕹 综合更新`
- 适用于全局机制、游戏设置、大厅规则等不归属于单一英雄或事件的改动。

### 4.5 错误修复
- 一级分区：`## 🐛 错误修复`
- 模块分类（H3）：`### 英雄`、`### 随机事件`、`### 地图`
- 条目格式：`- **[对象名]：** 修复了...的问题`

```markdown
## 🐛 错误修复

### 随机事件

- **任务：钢化你心：** 修复了当玩家心之钢层数为负数时，完成任务会因倍率效果导致负数进一步扩大的问题；负心之钢状态下不会再因任务奖励倍率产生额外惩罚
- **赌徒：心之钢：** 修复了当玩家心之钢层数为负数时，赢得事件会因倍率效果导致负数进一步扩大的问题
```

## 5. 文案风格与去 AI 化规范

1. **避免机械式加粗前缀**：严禁机械套用公式化前缀（如“`**触发条件放宽：** 降低门槛`”、“`**定向反转机制：** 重做规则`”），应直接陈述事实。
2. **消除公文式填充词与假大空评价**：
   - 🚫 避免：“旨在降低……以提升……体验”、“大幅减少极端负面情况”、“确保交互逻辑的合理性与严密性”。
   - ✅ 推荐：直接写出具体机制行为与数值。
3. **数字与状态变化简洁直接**：优先使用 `由 A 降低/增加/调整至 B`，不用冗长的过渡段落。
4. **严格遵循术语表（[`terminology.md`](terminology.md)）**：
   - 严禁在玩家侧使用内部词汇（如“审核”、“发放”、“OCR”、“持久化”、“编排”等）。
   - 正确使用称号术语（“获得称号”、“成就挑战”、“地图限定称号”）。
