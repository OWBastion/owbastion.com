# Portal 术语表

本术语表是 `apps/portal` 及其管理后台全部中文文案的唯一来源。新增或修改
任何文案前，必须先查本表；接口字段、数据库字段和 Bastion 消费的英文枚举值
保持不变，不把中文术语反向写入这些契约。

术语表只收录跨页面复用或容易产生偏差的词汇。页面内一次性的说明文字、错误
提示语气和句式规范见 [`portal-copy-guidelines.md`](portal-copy-guidelines.md)。

## 基本概念

| 术语 | 用法 |
| --- | --- |
| 称号 | `title_catalog` 中的实际称号名称，例如“开拓者”“征服者”“主宰”。 |
| 地图称号 | 作用范围限定为单张地图的称号。 |
| 地图称号规则 | 权威规则实体，定义称号、完成条件、截图规则、展示方式、称号槽位和生命周期。 |
| 称号槽位 | 地图称号在地图奖励中的分类；不是称号名称，也不是游戏难度。 |
| 地图例外 | 某张地图对权威规则的启用、停用或字段覆盖。 |
| 称号系列 | 称号的 `category` 字段，展示层统一写“系列”，例如“极限操作系列”。 |
| 成就挑战 | 通过提交截图核对的称号挑战（`family = achievement`），玩家页面统一使用。管理后台对同一类挑战可写“称号挑战”。 |
| 地图通关 | 玩家页面称呼单图通关类挑战（`family = map`）的用语。 |
| 地图挑战 | 管理后台对 `family = map` 挑战的称呼。 |

## 标准地图称号

| 代码 | 称号名称 | 中文槽位术语 | 当前完成条件 | 展示方式 |
| --- | --- | --- | --- | --- |
| `PIONEER` / `pioneer` | 开拓者 | 开拓者槽位 | 在新地图内测/公测中完成对应地图地狱通关（群内审核发放）。 | `map_pioneer` |
| `CONQUEROR` / `conqueror` | 征服者 | 征服者槽位 | 通关对应地图传奇难度。 | `map_name_suffix` |
| `DOMINATOR` / `dominator` | 主宰 | 主宰槽位 | 通关对应地图地狱难度。 | `map_name_suffix` |

“先锋”和“支配者”只作为历史代码语义或外部英文枚举的解释，不作为 Portal
称号名称或槽位文案单独使用；分别统一写为“开拓者”和“主宰”。

## 展示方式

| 枚举值 | Portal 文案 | 含义 |
| --- | --- | --- |
| `fixed` | 固定称号 | 直接使用称号名称。 |
| `map_pioneer` | 地图名 + 开拓者 | 使用地图名（或地图专用前缀）与“开拓者”组合展示。 |
| `map_name_suffix` | 地图名 + 后缀称号 | 将称号名称作为地图名后的后缀展示。 |

“地图先锋”不再作为展示方式文案使用；“段位”不用于描述地图称号槽位。

## 称号范围与提交方式

| 枚举值 | Portal 文案 | 含义 |
| --- | --- | --- |
| `global` | 全局称号 | 不限定地图的称号，玩家侧分组小标签统一写“通用称号”。 |
| `map` | 地图称号 | 限定地图的称号，分组小标签可写“限定地图”；不写“地图专属”。 |
| `manual` | 手动提交 | 通过提交截图核对获得。 |
| `automatic` | 自动提交 | 满足条件后自动获得，无需提交截图。 |

玩家页面描述自动获得类目标时，标题写“自动获得”，不写“自动发放”或“自动提交”。

## 绑定与 QQ

| 术语 | 用法 |
| --- | --- |
| BattleTag / 战网 ID | 玩家身份，格式为“玩家名称#数字 ID”，例如 `玩家名称#1234`。 |
| 邀请码 | 管理员为指定 BattleTag 生成的绑定凭据；玩家复制后按“口令”分发。 |
| 验证 | 玩家在 QQ 群内手动输入 `@` 并从列表选择机器人后发送 `/验证 <code>`，用于登录或绑定。 |
| 绑定申请 | 玩家发起绑定后等待处理的记录。 |
| 历史称号迁移 | 将历史持有者记录关联到当前平台玩家账号的过程。 |

## 玩家侧禁用内部词

以下词汇只在管理后台或玩家确实需要理解时使用，面向玩家的普通文案不要出现：

- 审核、人工审核（玩家侧统一写“核对”）
- OCR、OCRKit、识别模型
- 发放（玩家侧写“获得”）、编排、持久化
- 迁移（玩家侧指账号迁移时除外）、分发

## 修改前检查

1. 先查本表，确认是称号名称、称号槽位、展示方式、状态词还是产品流程术语。
2. 复用表中的中文；若现有数据与本表冲突，优先保留数据中的 `titleKey` 和
   枚举值，在展示层统一中文。
3. 若需要新增术语或改变标准称号名称，先更新本表及其对应的权威数据，再
   修改页面文案。
4. 状态词优先复用统一文案，不在页面内另造说法；加载状态加省略号。
5. 修改后搜索“这里”“开放后”“正在”“完成后”“审核”“OCR”“发放”
   等高风险词，并检查空状态、加载状态和错误状态。
