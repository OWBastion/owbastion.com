# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

主要用户是《躲避堡垒 3》的玩家：他们在游玩前查看事件、地图、成就和公开记录，提交截图证据，并查看自己的绑定身份、称号和提交状态。次要用户是管理员：他们审核提交、授予或撤销称号、维护目录和处理玩家绑定。

## Product Purpose

Portal 是《躲避堡垒 3》的玩家社区与平台操作入口，连接公开内容、玩家记录和受权限保护的管理流程。成功意味着玩家能了解当前可用内容、完成并提交挑战、清楚看到状态；管理员能在平台内维护业务数据并完成可审计的决定。

## Positioning

平台统一维护 Bastion 生态的当前事件、地图、称号、挑战元数据和业务状态，并通过 Portal、API、QQ 登录、OCR 识别与审核流程形成玩家记录闭环。Portal 展示平台拥有的公开事实，Bastion、QQBot 和 OCRKit 各自保留明确的实现、入口和识别边界。

## Operating Context

玩家通过浏览器访问公开目录、QQ 登录后的玩家中心和截图提交流程。平台 API 与 D1、R2、Queue 协作保存业务状态和私有提交证据；OCRKit 只提供截图识别；管理员通过受会话保护的 `/admin` 工作区处理审核、授予和目录维护；Bastion 在构建时通过 Agents API 读取平台元数据。

## Capabilities and Constraints

- 当前 Portal 能力包括公开目录、QQ 浏览器登录、玩家中心、截图提交与状态查询，以及受保护的管理面。
- 平台拥有当前事件、地图、称号、挑战元数据、玩家业务状态、私有证据和审核/授予编排。
- OCRKit 仅负责无状态截图识别；匹配、持久化、复核、授予、审计和状态转换由平台负责。
- 私有截图、审核数据、凭据和个人标识不得进入公开页面或提交到仓库。
- Portal 文案使用简洁中文和既有术语；API 与数据库的英文枚举保持不变。未开放能力不得描述为当前功能。
- 管理决定不应强制要求填写理由或备注；审计理由可以为空。

## Brand Commitments

- 产品名称：`《躲避堡垒 3》`。
- Portal 面向玩家使用简洁、克制、具体的中文，沿用现有术语表和状态词。
- Portal 的公开页面、玩家中心和管理面属于同一产品，但公开内容、玩家数据和管理数据必须保持清晰边界。

## Product Principles

- 一份事实由一个明确的系统负责维护。
- 玩家看到的状态应准确反映平台业务状态，而不是内部处理猜测。
- 公开内容与私有证据、审核数据和个人标识保持分离。
- 管理员应获得完成决定所需的数据和选择权，非必要输入不得成为阻塞条件。
- 跨服务协作保持幂等、可审计，并尊重 Bastion、QQBot、OCRKit 的边界。
